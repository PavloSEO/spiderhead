# SEOHEAD Desktop roadmap

Desktop remains a native Python/PyQt5 presentation adapter over the core CLI and local stdio MCP contracts. Feature availability follows the connected core and retained evidence.

| Area | Development priority | Release gate |
|---|---|---|
| Presentation | Shared theme tokens, native layouts, bounded models and accessible controls | Integrated runtime checks at supported window sizes |
| Projects and scans | Explicit ownership, independent runs and retained evidence | Open, collect, retain, inspect, compare and verify through core contracts |
| Scheduling | Core-owned settings and due decisions; explicit dispatch | Compatible schedule command and revision contracts |
| Providers and MCP | Honest readiness, redaction and explicit configuration changes | No hidden requests, paid calls or credential exposure |
| Packaging | Bundle the application and a compatible core together | Build provenance and clean-machine acceptance per platform |
| Capacity | Bounded queries, lazy views and measured resource use | Actual retained-data measurements; no inference from a small fixture |

Theme and layout values come from `src/seohead_desktop/theme/tokens.json` and [shared component tokens](docs/canvas-tokens.md). Native table and intent contracts are in [tab contracts](design/tab-contracts.md). Packaged brand and application icons live in `src/seohead_desktop/assets/brand/` and `src/seohead_desktop/assets/app/`; preserve their manifests and license notices.

Final verification must identify the integrated application and core revisions. Native visual acceptance, Windows/Linux runtime, installers and large-data capacity are separate checks; an offscreen suite alone does not establish them.
