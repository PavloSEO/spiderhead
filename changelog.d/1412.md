- `LOW_TEXT_RATIO` no longer fires on nearly every page of a modern site. The native
  crawl now measures `text_ratio` against the HTML with script, style and JSON data
  blocks removed instead of the raw response size, so the ratio describes markup
  overhead per unit of text rather than how much inline code a template ships. On the
  retained spiderhead.dev scan this changes the picture from 353 of 374 HTML pages
  under the old 10 percent line to only the genuinely markup-heavy minority. The
  finding is additionally suppressed for any page whose word count clears the
  `thin_content_words` threshold THIN_CONTENT already uses — deliberately the same
  line, so the two checks can never disagree about whether a page has content; the
  1300-2800-word pages the old measure flagged are not missing copy. Threshold stays
  configurable as `thresholds.low_text_ratio_pct` and severity stays notice.
