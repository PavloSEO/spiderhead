- Hrefs that cannot become fetchable link targets leave evidence instead of
  vanishing. Link parsing drops an unparsable href (malformed syntax, e.g. a
  truncated `http://[invalid`) or a non-http(s) scheme (`mailto:`, `javascript:`)
  with no trace: the source page keeps nothing to say it points at something
  broken. The new opt-in crawl setting
  `discovery.record_invalid_targets` records each rejection per page
  — the raw href exactly as written plus the reason (`unparsable_syntax` /
  `unsupported_scheme`) — through the parser, the crawl record, the scan schema
  (`pages.invalid_link_targets_json`) and the analyzer frame, and the new
  `INVALID_LINK_TARGET` check turns the pages that have them into findings with
  the raw values as evidence. A missing href and a pure in-page `#anchor` are
  absence, not defects, and are never recorded; a measured clean page records an
  empty list; a crawl that ran without the setting skips the check honestly
  instead of reporting a clean site nobody measured. Rejected targets are data:
  they never enter the frontier. The setting is off by default and is recorded
  in the run manifest like every finding-changing setting.
