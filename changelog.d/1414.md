- New check `MISSING_HSTS_ON_REDIRECT_HOP` (notice, once per site): a redirect hop
  between the host variants of the start URL that answers without a
  `Strict-Transport-Security` header. `MISSING_HSTS` judges only the final response
  of a crawled page, so the www-to-apex and http-to-https hops a browser can arrive
  on were invisible to every scan — on spiderhead.dev the www host answers 301 to the
  apex and is never fetched by the crawl. The new opt-in setting
  `analysis.redirect_hop_hsts_probe` walks the four origin variants (https/http,
  bare/www) hop by hop and records each response's status and HSTS header; the
  observation is retained in the scan, so offline reanalysis re-judges the same hops
  instead of re-probing or losing the finding. Without the setting every audit
  reports an honest skip and nothing else changes.
- The probe toggle rides outside the frozen config header and the extension
  vocabulary: a rolled-back build never meets the key, the config fingerprint
  ignores it (it is an audit-time measurement toggle, not a collection rule),
  and the retained probe observation in the scan is what offline reanalysis
  re-judges.
